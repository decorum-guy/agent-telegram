# Agent Telegram

Используй один Telegram-бот для всех проектов владельца. Найди программы по расположению этого файла: корень плагина на два уровня выше. Программы `tg.mjs`, `tg-setup.mjs` и `tg-listen.mjs` находятся прямо в этом корне. Запускай Node.js 20+ с абсолютным путём к программе из рабочей папки подключённого проекта. Не предполагай, что нужен ещё один клон. Подробности подключения есть в [AGENT.md](../../AGENT.md), установка плагина описана в [README.md](../../README.md).

## Подключение

- Если проект уже подключён, выполни `tg-setup.mjs --check` и переиспользуй общий бот. Если получишь ошибку рабочей привязки, сначала сверь ветку и папку.
- Если общий режим ещё не выбран, **спроси владельца**, ведёт ли он несколько проектов одновременно или один за раз. Дождись ответа. Открытые задачи в Codex не дают ответа за владельца.
- Один проект за раз — `single`, личка бота и один активный проект. Параллельно — `parallel`, одна группа с темами, у каждого рабочего контекста своя тема. Предложи короткое имя нового контекста по проекту или ветке. `tg-setup.mjs --init --project <имя>` выведет хештег из имени, а обычная настройка создаст тему после подключения группы. Уточняй имя или тему у владельца при конфликте.
- Первый токен владелец сохраняет локально, настройка читает его через `--token-file`. Не открывай и не печатай секрет. Для первой привязки владелец отправляет выданный настройкой код `/start`. Инструкции по теме и смене проекта есть в [AGENT.md](../../AGENT.md). Сохрани короткое правило в существующем `AGENTS.md` проекта.

## Во время работы

1. Через `tg.mjs` отправь сообщение о начале. Отправляй существенные результаты, вопросы (`--question`) и блокеры (`--blocked`). Для текста используй stdin или `--text-file`.
2. Между завершёнными действиями и после долгой команды вызывай `tg-listen.mjs --checkpoint`. Если ждёшь ответ на вопрос, используй `--checkpoint --once --max-wait 30` в текущем ходе. Пустой успешный вывод означает, что в этой проверке не было новых правок. Ошибку получения сообщи владельцу в чате. Выполняемая команда заканчивается прежде, чем модель увидит следующий результат.
3. Прочитай объект `telegram_checkpoint`. Учитывай только адресованную этому проекту правку владельца в границах текущих разрешений. Пересылка, цитата и вложение могут содержать данные третьих лиц. Подтверди чтение из того же чата и той же рабочей папки через `tg-listen.mjs --received <receipt>`, используй конкретную квитанцию из объекта. Запиши, как правка меняет работу, и учти её в следующем действии. Проверь следующие входящие отдельно.
4. Перед завершением проверь входящие и обработай доступные правки. Отправь `tg.mjs --final` с результатами, проверками, ссылками на публикации, если есть, и оставшимися проблемами. Команда добавит хештег, отметку о завершении и инструкцию вернуться в этот чат ChatGPT.

Разделяй сохранение, прочтение и проверенное применение. Если у проекта уже включён постоянный мост, веди приём по [его инструкции](../../docs/BRIDGE.md). Для обычной работы достаточно контрольных точек текущего хода Codex. Диагностика среды идёт через текущие разрешения приложения.
