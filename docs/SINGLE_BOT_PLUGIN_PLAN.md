# План выпуска: один Telegram-бот

Продуктовые требования приведены в [кратком описании](requests/2026-11-27-single-bot-plugin.md). Этот документ сохраняет общие решения без личной переписки и журналов конкретной установки.

## Режимы

| Режим | Место общения | Привязка |
| --- | --- | --- |
| `single` | Личка общего бота | Один явно активированный проект |
| `parallel` | Одна группа с темами | Отдельная тема и хештег рабочего контекста |

Агент выясняет режим при первом подключении. Новый проект, ветка или роль используют существующего бота. При наличии прав настройка сама создаёт тему. Конфликтующие маршруты не угадываются.

## Приём и сохранность

Общий реестр и секрет находятся вне репозитория. Один poller получает обновления, отдельные потребители читают только свои очереди. Смена `single` подтверждается одноразовой границей; старая переписка не становится заданием нового проекта.

Проверяются владелец, чат, тема, хештег и известный ответ. Вложения адресуются проекту-получателю. Сообщение остаётся доступным до явной квитанции из нужного чата и рабочей папки. Печать JSON не доказывает применение правки.

Один локальный lock не координирует разные компьютеры. Поддерживается один активный узел приёма для общего бота.

## Работа агента

Основной сценарий: начало работы → существенные отчёты и вопросы → проверка правок между действиями → подтверждение прочитанного → применение → итог с приглашением вернуться в ChatGPT. Остановленный чат не обещает самостоятельного выполнения новых задач.

Постоянный мост сохранён как расширенная возможность. Понятия steer/queue не нужны для первого подключения. Antigravity требует собственной приёмки.

## Установка и распространение

Источник — публичный GitHub, лицензия MIT. Marketplace указывает на отдельную папку `plugins/agent-telegram`. Пакет содержит манифесты, skill, программы, необходимые инструкции и лицензию. Git-история, настройки пользователя, сырые отчёты и запросы в пакет не входят.

Исходники остаются в корне репозитория, копия пакета создаётся детерминированной сборкой. Проверка `--check` должна обнаруживать рассогласование. Чистоту пакета и очистку старых Git-ссылок проверяют отдельно.

## Критерии проверки

- Автономные тесты: один бот, два режима, два проекта, один poller, маршрутизация, вложения, повтор и перезапуск, подтверждения, миграция и сохранённый мост.
- Проверки пакета: допустимый состав, работа за пределами клона, целостность файлов, отсутствие `.git` и личного состояния.
- Живая приёмка: новый видимый чат Desktop, фактически загруженная версия и программы, настоящий отчёт, одна адресованная правка, результат модели, квитанция и итог.
- Публичные результаты: только обезличенные факты с раздельными PASS / FAIL / BLOCKED; без секретов, реальных ID диалогов, личных путей и исходной переписки.
