# Постоянная связь с Codex

Это техническая инструкция для настройки и диагностики. Основной сценарий пользователя — обычные отчёты и текстовые правки, без выбора steer/queue.

## Что делает мост

`tg-bridge.mjs` сохраняет состояние конкретного проекта и адресует входящие точному диалогу и cwd. Общий транспорт хранит секрет, реестр и Telegram offset в `~/.agent-telegram`; мост каждого проекта — в `~/.agent-telegram/projects/<проект>`. Все проекты используют одного бота и один избранный приёмщик. Наличие сохранённого ID диалога не доказывает доступ к его runtime.

Постоянный мост является расширенным сценарием и не входит в основную живую приёмку активного Desktop-чата. Проверяй его локально в рамках согласованного подключения.

## Установка службы

Из корня проекта, с абсолютным путём к установленному набору:

```sh
node /absolute/path/to/agent-telegram/tg-setup.mjs --bridge install
node /absolute/path/to/agent-telegram/tg-setup.mjs --bridge status
```

Установка меняет пользовательские файлы интеграции и службу запуска: launchd на macOS, пользовательский systemd на Linux, планировщик на Windows. Она должна сохранять чужие настройки. Отключение и удаление своей интеграции — `--bridge stop` и `--bridge uninstall`. Рабочая копия плагина должна оставаться доступной по установленному пути; обновление/перемещение требует проверки службы.

## Codex CLI

```sh
node /absolute/path/to/agent-telegram/tg-bridge.mjs open --client codex-cli
```

Команда открывает управляемый диалог. Для проверки существующего runtime используется `register --client codex-cli` с точным ID сессии и endpoint, который реально принадлежит этому диалогу. Не угадывай ID по названию, последнему времени или соседней сессии. Поддержка команд и протокола должна быть проверена на установленном Codex.

## Открытый Codex App на macOS

Ограниченный путь обычного текста через очередь App регистрируется **из нужного чата**:

```sh
node /absolute/path/to/agent-telegram/tg-bridge.mjs register --client codex-app --app-queue --check-only
node /absolute/path/to/agent-telegram/tg-bridge.mjs register --client codex-app --app-queue
```

`--check-only` читает условия без регистрации и отправки. Успех содержит `registrationChanged: false` и `deliveryVerified: false`: это ожидаемо и не означает тест доставленного сообщения.

Для `capability: app-queue` поддерживается обычный текст. Вмешательство в текущий ход, его остановка, вложения и ответы на вопросы не становятся доступными автоматически. `/stop` и пауза удерживают новые отправки моста; уже переданное может исполниться. Эти ограничения нельзя скрывать общей фразой «мост работает».

## Проверка доставки

```sh
node /absolute/path/to/agent-telegram/tg-bridge.mjs status
```

Проверь свой проект, `active`, `cwd`, capability, ошибки runtime и список deliveries. Свежий тест: сообщение от разрешённого владельца в правильное место → сохранённое событие → один ход нужного Codex → правильный текст → явный ACK того же receipt.

Сообщение с явным хештегом проекта из общей темы группы может адресовать его мост; конфликт с другой закреплённой темой не допускается. Исходное место сообщения сохраняется для квитанции.

В полученной инструкции есть точные event ID и receipt. Для подтверждения используй указанную команду `tg-bridge.mjs ack <event-id> <receipt>` из того же диалога/cwd либо поддерживаемую runtime строку `TG_ACK`. Не подтверждай чужое или непрочитанное событие.

👍 означает сохранение. 👀 означает явный ACK целевого агента. Применение правки подтверждается отдельным результатом задачи. Если исход передачи неизвестен, сначала проверь квитанцию и историю; не отправляй повторно автоматически.

## Активный чат без моста

Основной сценарий Codex Desktop использует `tg-listen.mjs --checkpoint` и подтверждение `--received` из того же чата. Эти команды описаны в [инструкции агенту](../AGENT.md). Обычный `--drain` сохранён для ручной диагностики вне этого сценария.

## Расширенные команды

Существующие адаптеры сохраняют pause/resume, `/now` и управление вопросами в пределах своих возможностей. Их не нужно объяснять до первого рабочего обмена. Claude-код сохранён для совместимости, но в этой версии не является основным проверяемым пользовательским путём. Antigravity ещё требует отдельного адаптерного аудита.

Если компьютер спит/выключен или нет сети, доставка не подтверждена. Telegram ограничивает хранение ещё не полученных обновлений; см. [официальный Bot API](https://core.telegram.org/bots/api#getting-updates). Для нескольких машин нужен согласованный один узел приёма; локальный lock не защищает от второго компьютера.
