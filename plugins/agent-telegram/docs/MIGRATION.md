# Переход с отдельных ботов на одного

Существующие каталоги и историю не удалять. Новый общий транспорт использует `~/.agent-telegram/projects.json` и `~/.agent-telegram/.secrets/telegram.env`. Состояние мостов остаётся раздельным в `projects/<имя>/bridge.json`.

## Перед запуском

1. Остановите старые приёмщики и службы этой установки. Не завершайте чужие процессы по одному похожему имени или старому PID.
2. Сохраните локальную резервную копию `~/.agent-telegram` с закрытым доступом: там секреты и переписка. Резервную копию не загружать в GitHub и не печатать в чат.
3. Выберите одного бота и режим. Если раньше были разные боты, подтвердите локально, какие старые привязки должны перейти к выбранному боту. Разные токены не объединяются автоматически.

## Совместимые старые проекты

Из папки существующего проекта:

```sh
node /absolute/path/to/agent-telegram/tg-setup.mjs --migrate --mode parallel
```

Либо `--mode single` для последовательной работы. Если совместимых старых проектов несколько, в single сначала потребуется одноразовое подтверждение `/activate <код>`; до него неоднозначные входящие сохраняются отдельно. Точный список опций — `tg-setup.mjs --help`. Если нужен другой существующий проект, укажите `--project <имя>`.

Миграция проверяет совпадение токена, владельца, группы и уникальность хештегов/тем. При конфликте она останавливается до объединения состояния. Старые inbox-пути сохраняются: историю, очередь и sent-журнал не нужно переносить или очищать. Отдельные номера пользователей и токены не печатаются.

Если обнаружены разные старые токены, это **видимый блокер автоматической миграции**. Выбор общего бота и перепривязка несовместимых старых проектов выполняются отдельно после резервной копии; не удаляйте каталоги, чтобы заставить проверку пройти. Эта версия не обещает бесшовно объединить произвольные установки разных ботов.

Старое явное поле `hub` в файле проекта нельзя использовать для запуска конкурирующего poller. После согласованной миграции оно удаляется из переносимой конфигурации; общий транспорт при необходимости задаётся единым `TG_HUB`.

## После перехода

Проверьте `--check`, правильный хештег/тему, отчёт и встречную правку. Запустите два проекта в parallel и убедитесь, что входящие не пересекаются. При single второй проект активируется только явно через `--activate`; предыдущий обработчик должен быть остановлен. Одноразовый `/activate <код>` подтверждает границу сообщений; до него новый проект не получает старую личную переписку. До реальной проверки не объявляйте миграцию завершённой на компьютере владельца.

Перенос между компьютерами выполняется с одним активным узлом приёма. Не запускайте оба компьютера с одним токеном одновременно.
